# OKX 永续合约量化交易系统

> 位置：`quant-okx`
> 依赖：Python 3.9+（本机 3.11.5），以标准库为主；走 socks5 代理需要 `requests` + `PySocks`
> 状态：回测/对比/寻优/模拟盘可运行；实盘只读接口已在真实账户调通

**上真钱之前必须知道的三件事：**

1. 下单、挂止损、撤止损、市价全平这四条写入路径**还没有实测**，先用 OKX 模拟盘跑通一次完整的开仓 → 止损 → 平仓。
2. 机器人现在只管**它自己开的仓**。同一个合约上有你手动开的仓时，它不平、也不在这个合约上开新仓。
3. 账上可用保证金不够开最小一张单时，它只观望、不开仓。

---

## 一、这套东西是什么

一个**能真下单**的 OKX 永续合约量化交易系统，四层分离：

| 层 | 文件 | 职责 |
|---|---|---|
| 通道层 | `okx_client.py` | OKX v5 REST 签名、socks5 代理、限速重试（下单类请求超时不重发） |
| 信号层 | `strategy.py` + `indicators.py` | 三种策略：趋势 / 突破 / 均值回归 |
| 风控层 | `risk.py` | 风险百分比仓位 + 日亏 / 回撤两道熔断 |
| 执行层 | `engine.py`（回测）+ `broker.py`（实盘/模拟盘）+ `trader.py`（主循环） | 撮合、下单、止损校验、对账 |

**核心安全设计**：回测里信号在 bar 收盘产生、**下一根 bar 开盘成交**，没有未来函数；
实盘只吃 `confirm=1` 的已收盘 K 线，绝不看正在跳动的未收盘 bar。

## 二、五分钟上手

### 1. 体检（不需要 API，先确认网络）

```powershell
cd quant-okx
python run.py doctor
```

> **国内网络（2026-11-16 实测，以这段为准）**：
> - 唯一能下单的组合是 **`www.okx.com` + socks5 代理**（本机 v2rayN 在 `socks5h://127.0.0.1:10808`，可用环境变量 `OKX_PROXY` 改）。
> - `okx.com`（不带 www）能直连，但**只支持查询**，下单/设杠杆/撤单全部被拒。别因为它能读行情就以为能用。
> - `my.okx.com`、`www.okx.ac` 的 DNS 同样被污染。
> - 代理挂掉时机器人看不到行情也管不了仓位，持仓只剩交易所上的止损单在保护。

### 2. 回测（不需要 API）

```powershell
python run.py backtest                          # 默认 trend / 15m / 1500 根
python run.py backtest --bar 1H --bars 3000     # 换周期
python run.py compare                           # 三策略同段行情 PK
python run.py tune --strategy trend --bar 1H    # 网格寻优
```

### 3. 填 API 凭据

编辑 `.env`：

```
OKX_API_KEY=你的key
OKX_API_SECRET=你的secret
OKX_PASSPHRASE=创建时设的口令
OKX_SIMULATED=1
```

- `OKX_SIMULATED=1` → 模拟盘（**先在 OKX 网页切到「模拟交易」并在模拟环境另建一套 key**）
- `OKX_SIMULATED=0` → 实盘
- 权限只要「交易」，**不要给「提币」**，务必绑 IP

### 4. 模拟盘（真实行情 + 虚拟资金，零风险）

```powershell
python run.py paper
```

每轮打一行日志，账本落盘在 `data\paper_state.json`，随时 `python run.py status` 查。

### 5. 实盘

```powershell
python run.py live            # dry-run：只打印「将要下什么单」，不真下单
python run.py live --real     # ★ 真实下单，动真钱 ★
```

用 `启动.ps1` 有中文菜单：`powershell -ExecutionPolicy Bypass -File ".\启动.ps1"`

**上实盘的顺序（一步都别跳）：**

1. `python verify_engine.py` 和 `python verify_live_safety.py` 都全绿
2. `python run.py live`（只算不下单），看日志里的策略本金、持仓、有没有告警
3. `.env` 里 `OKX_SIMULATED=1`，用 OKX 模拟盘跑通一次完整的开仓 → 止损 → 平仓
4. 最后才是 `python run.py live --real`

**实盘通道的行为：**

- **策略本金**：`config.json` 的 `live.capital_usdt` 写了就用它；写 0 则取首次启动时账上的可用保证金并记住。熔断和仓位都按「本金 + 已实现盈亏 + 本策略浮盈亏」算，账上别的仓位怎么波动都不影响。
- **开仓**：发单后会查单确认成交，再确认交易所上真的有止损单；没有就补挂，补不上就立即平仓（`live.require_exchange_stop`）。
- **止损两道**：交易所上的止损单 + 本地每轮检查（价格击穿而仓位还在就市价平）。交易所那张止损单停在开仓时的位置，不跟着移动止损走。
- **开仓信号有保鲜期**：只认最后一根已收盘 K 线的信号；收盘后太久才看到（15m 周期上限 225 秒）或现价离信号价超过 1 倍 ATR 就放弃。重启、断网恢复后不会补做旧信号。
- **每轮对账**：策略此刻应为空仓而手里还有仓，就平掉。带仓重启时也按这条处理。
- **同一模式只能跑一个进程**，第二个会被拒绝启动。
- 实盘账本在 `data\ledger_<通道>_<合约>.json`。**别手动删它**，里面记着在场仓位的止损价。

`config.json` 里新增的可选项（不写就用默认值）：

| 项 | 默认 | 含义 |
|---|---|---|
| `live.capital_usdt` | 0 | 划给本策略的本金；0 = 首次启动时取可用保证金 |
| `live.require_exchange_stop` | true | 确认交易所上没有止损单又补挂不上时，立即平仓 |
| `live.fee_pct` / `live.slip_pct` | 0.0005 / 0.0002 | 算仓位时计入的来回成本 |
| `loop.history_bars` | 1200 | 启动时拉多少根 K 线做指标预热 |
| `loop.max_entry_delay_s` | 0 | 开仓信号保鲜期（秒）；0 = 周期的 1/4，最多 300 秒 |
| `loop.max_entry_drift_atr` | 1.0 | 现价离信号价超过几倍 ATR 就放弃开仓 |
| `backtest.funding_pct_8h` | 0.0001 | 回测计入的资金费率（每 8 小时），多空都付；0 = 不计 |

## 三、策略说明

三套策略统一接口，`config.json` 里 `strategy` 切换。

### `trend` — 趋势脉冲 v2（默认主力）

v1 实测翻车（下跌趋势里 9 笔做多全亏，胜率 16.7%），v2 加了**大周期趋势闸门**：

- **大方向闸门**：价格必须在 EMA(200) 之上才允许做多、之下才允许做空
  → 下跌通道里的反弹金叉一律不做多，从源头掐掉接刀
- **方向**：EMA(fast) > EMA(slow) + 收盘价在慢线同侧
- **过滤**：ADX(14) ≥ `adx_min`（4H 用 18，1H 用 28），震荡市不碰
- **防追高**：价格离慢线不超过 `max_ext_atr` 倍 ATR
- **止损**：入场价 ∓ ATR × `atr_mult`
- **移动止损**：Chandelier，多单抬到 `最高价 - ATR × trail_mult`
- **出场**：快线下穿慢线 / 大周期转向 / 触移动止损
- 单向持仓、不加仓、可做空

关键参数：`regime_len`（大周期闸门，默认 200）、`adx_min`（最重要的过滤参数）

### `breakout` — 唐奇安突破（海龟简化）

突破 20 根高点做多、破 20 根低点做空；跌破 10 根低点离场；ATR × 2 止损。

### `meanrev` — 均值回归

RSI(14) ≤ 30 且破布林下轨做多，RSI ≥ 70 且破上轨做空，回到中轨离场；ATR × 1.8 止损。

### 参数寻优

```powershell
python run.py tune --strategy trend --bar 1H --bars 2000
```

输出 Top 10（按夏普排序），然后一键写入：

```powershell
python run.py apply --strategy trend --params '{"fast":8,"slow":34,"adx_min":25.0,"atr_mult":2.5,"trail_mult":3.0}'
```

## 四、风控（实盘命门，全在 `config.json` 的 `risk` 段）

| 参数 | 默认 | 含义 |
|---|---|---|
| `risk_pct` | 1.0 | **每笔最大亏损 = 权益的 1%**，仓位由止损距离反推张数 |
| `max_leverage` | 3.0 | 名义价值 ≤ 权益 × 3 |
| `max_daily_loss_pct` | 3.0 | 单日亏 3% → 熔断，当天不再开仓（次日自动解除） |
| `max_drawdown_pct` | 15.0 | 从峰值回撤 15% → 全局熔断，需人工 `reset-halt` |
| `max_positions` | 1 | 最多同时 1 个持仓 |

**仓位公式**：

```
风险金额 = 权益 × risk_pct%
每张止损损失 = |入场价 - 止损价| × ctVal
张数 = 风险金额 / 每张止损损失   → 向下取整到 lotSz
```

也就是说：**止损被打了，亏损在 risk_pct 附近。** 这是全系统最重要的一行。
实盘和模拟盘算张数时会把来回手续费和滑点也算进「每张止损损失」，所以张数比上面的公式略小；
回测引擎没有这一步。跳空越过止损位时实际亏损会超过预算。

另外几条会直接拒单的情况：止损在入场价的错误一侧（价格已穿过止损位）、止损距离小于 0.05%、
逐仓模式下止损比强平线还远、算出的张数低于最小下单量。实盘还会按可用保证金给仓位封顶。

熔断细节：

- 权益口径：模拟盘是虚拟账本的权益；实盘是**策略权益**（本金 + 已实现 + 本策略浮盈亏），不是账户总权益，也不是可用余额
- 「一天」按 **UTC 日期**切换
- 日亏熔断跨日自动解除；回撤熔断**不自动解除**，必须人工解除
- 熔断触发时若还有本策略的持仓 → 强制平仓
- 状态文件按通道分开：`data\risk_state_paper.json` / `risk_state_live-real.json`（真钱）/ `risk_state_live-sim.json`（OKX 模拟盘）/ `risk_state_live-dry.json`
- 解除熔断：**先停掉机器人**，再 `python run.py reset-halt`（加 `--tag live-real` 只解除某个通道）。
  解除时峰值和日初权益会从当前权益重新起算。机器人在跑时解除无效，它内存里的状态会把文件覆盖回去

**上实盘前必须跑这两个（都是纯离线）：**

```powershell
python verify_engine.py        # 24 项：仓位换算、杠杆上限、熔断、止损撮合
python verify_live_safety.py   # 56 项：用假交易所演断网、崩溃、止损没挂上、手动仓位等情况
```

**不是全绿就别上实盘。** 改了 `okx_client / risk / broker / engine / trader` 任何一个之后也要重跑。

## 七、常见报错对照

| OKX 错误码 | 含义 | 修法 |
|---|---|---|
| `50111` | API Key 无效 | 检查 `.env` 的 key 有没有多余空格 |
| `50113` | 签名错误 | Secret 填错，或系统时间偏差 > 30s |
| `50105` | Passphrase 错误 | 口令与创建时不一致（不是登录密码） |
| `50101` | 权限不足 | API Key 要勾「交易」 |
| `51000` | 参数错误 | 通常 sz 不满足 `lotSz`/`minSz`（本系统已自动对齐） |
| `51008` | 余额不足 | 权益太小，算出的张数不够最小下单量 |
| `401` | 环境不匹配 | 模拟盘 key 打到实盘 → 改 `OKX_SIMULATED` |
| `50011` | 请求过于频繁 | 已内置限速桶 + 退避重试，正常不会遇到 |
| `50102` | 时间戳过期 | 本机时钟偏差太大；启动时已按交易所时钟校准，仍报就检查系统时间 |
| `51603` | 订单不存在 | 下单后查单时出现 = 那张单确实没成交，属正常判定 |
| `NET_AMBIGUOUS` | 下单请求中途断网 | 不是 OKX 的码。机器人不会重发，会按订单编号查单确认；查不到就留「在途记录」，下一轮按交易所持仓对账 |

日志里几种情况的含义：

| 日志 | 含义 |
|---|---|
| `止损单挂不上，已立即平仓` | 开仓成交后在交易所上查不到止损单，补挂也失败。**每次开仓都这样**就说明止损单接口的参数有问题（这条路径还没实测过） |
| `开仓信号已过期 … 放弃` | 信号那根 K 线收盘太久才看到（重启、断网、熔断刚解除） |
| `合约上另有非本策略持仓` | 这个合约上有你手动开的仓，机器人不开新仓 |
| `账上可用保证金只有 … 暂不记策略本金` | 钱被别的仓位占着，机器人只观望 |
| `对账不一致 … 平仓` | 策略此刻应为空仓（或方向相反）而手里有仓，常见于带仓重启 |
| `已经有一个同模式的机器人在运行` | 同一通道开了第二个进程，被拒绝 |

设计上已处理的运维坑：
- **Windows 控制台 GBK** → `run.py`/`trader.py` 强制 `stdout.reconfigure(utf-8)`
- **`启动.ps1` 编码** → 已写入 UTF-8 with BOM，PS 5.1 不会按 GBK 读崩
- **`.env` 编码** → 纯 ASCII，任何编辑器打开都不乱

## 八、实战建议（工程建议）

1. **先模拟盘跑满一周**，至少经历一次大波动，再上真钱。
2. **首笔实盘用最小资金**（比如 50 USDT），跑通交割、止损单、平仓全链路。
3. **`risk_pct` 不要超过 2%**。1% 意味着连亏 10 次才亏 10%，还有得救。
4. **15m 以下周期不适合这套趋势策略** —— 回测里手续费能吃掉 2.5% 本金，
   周期越短越亏手续费。趋势策略请用 `1H` 或 `4H`。
5. **一定要在 OKX 后台给 API 绑 IP**，并且不给提币权限。key 泄露的损失上限由这两条决定。
6. **单一策略单一标的不叫分散**。真要大资金，多标的 + 低相关性才叫分散。
7. 回测好看 ≠ 实盘赚钱。滑点、资金费率（永续每 8 小时收一次）、极端行情插针，
   回测都没有完全建模。**资金费率尤其要留意，长期持仓成本不低。**
   （2026-11-16 起回测按固定 0.01%/8 小时计资金费，不是历史真实费率。）

> **注意**：当前 `config.json` 是 DOGE-USDT-SWAP / 15m / 每笔风险 3% / 20 倍杠杆 / 日亏 8% / 回撤 50%，
> 和上面第 3、4 条以及下面「15m 不适合这套策略」的结论不一致。

## 九、实测基线（2026-11-16 · 全部真实 K 线，无拟合）

> **读这一节之前**：下面两张表是**审查前的引擎**跑出来的，没有重跑。现在的引擎多了资金费、
> 跳空按开盘价成交、开盘已过止损位不开仓、逐根按浮盈亏判熔断，重跑出来的数字会比表里低一些。
> 标题里的「无拟合」也要打折扣：两套参数是 `tune2.py` 在这些 K 线上扫出来的。
>

### 三条必须知道的结论

**① 参数和周期是绑死的。**
1H 最优 `adx_min=28`，4H 最优 `adx_min=18`。拿 1H 的参数去跑 4H，
BTC/ETH/SOL 三个标的全亏（实测 -3.08% / -3.34% / -0.46%）。
**换周期必须重新 `tune2.py`，不许跨周期套参数。**

**② 15m 不适合这套策略。**
15m 上手续费吃掉 2.5% 本金，样本期又是震荡下行，任何参数组合都做不出正收益。
**趋势策略请用 1H 或 4H。**

**③ 胜率只有 27~32%，靠盈亏比活。**
趋势策略的典型形态：**10 笔亏 7 笔小亏，3 笔赚到大钱**。
看到连续亏损是正常的，只要单笔亏损被 1% 风险预算卡住，本金就伤不到。
**心理上受不了连续小亏的人，别跑趋势策略。**

### 开发过程中实测到的 4 个坑（都已修）

| 坑 | 现象 | 修法 |
|---|---|---|
| 首次启动重放历史信号 | 一口气开平 12 次，白送手续费 | 基线设到倒数第二根 bar，历史信号作废 |
| Windows 控制台 GBK | `✓ ═` 直接 UnicodeEncodeError 崩掉 | `stdout.reconfigure(utf-8)` |
| `candles` 接口截断 | 目标 3000 根只给 1440 根 | 两阶段：candles 300/页 + history-candles 100/页 |
| **跨标的验证读错缓存** | ETH/SOL 全在读 BTC 的 K 线，验证结果全是假的 | `fetch_candles` 显式传 inst_id |

最后那个坑最危险 —— 它让 SOL 显示"0 笔交易"才暴露出来。
**如果不是零信号暴露，就会拿着假验证结果误上实盘。**
